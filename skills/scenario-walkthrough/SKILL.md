# 场景走查（Scenario Walkthrough）

> **一句话**：先基于真实功能产出"文字版操作场景"（点哪→输什么→得到什么），再按场景逐条读代码模拟执行，找链路断裂、权限漏洞、状态机矛盾、补丁叠补丁与无法操作点。
>
> **版本**：v3（2026-08-14）三层结构——A 主线（必做）/ B 工具库（按需）/ C 检查沉淀。继承 v2 系列沉淀：素材剧本化、复杂度分级 L1-L9、探索会话 SBTM、规则真值表、变更影响分析、风险评分、迭代停止准则。

## A. 主线流程（先读这个，2 分钟掌握全流程）

```
1 能力清单 → 2 素材剧本+覆盖矩阵 → 3 分级走查 → 4 走查报告 → 5 修复闭环 → 6 迭代停止
                                                              ↑________循环直到收敛________|
```

### 步骤 1：调研功能清单

- **动作**：用 Explore 子代理或 grep 盘点当前真实能力——页面/入口、数据字段、权限矩阵、状态机、硬限制
- **产出**：`docs/walkthrough/capabilities.md`，每条能力给 C-ID（如 C-01 创建计划、C-02 完成计划）
- **铁律**：素材里出现清单外功能 = 素材错误（P-4：曾写"计划置顶"，实际置顶只有清单有）

### 步骤 2：生成素材剧本 + 覆盖矩阵

- **动作**：产出操作链素材（点哪→输什么→得什么），带 S-ID，落盘 `docs/walkthrough/scenarios.md`
- **格式**：`S-xx | 类型(如 L4·状态机长链) | 操作链 | 预期结果 | 覆盖 C-ID | 走查等级(深度/快速)`
- **铁律**：覆盖 C-ID 必须存在于步骤 1 清单；有状态机/并发/离线/权限能力的项目必须含 ≥1 条 L4+ 链
- **工具**：写素材选等级看 B1；生成矩阵看 B2；遇到条件 ≥2 的规则看 B3

### 步骤 3：分级走查

- **动作**：按素材的走查等级分流——**深度**链自己 Read 原文逐层走，**快速**链 grep 确认存在即过
- **深度链路**：`页面 → service → store → 云函数 → 数据库/推送`
- **产出**：每链「通/不通 + 证据(文件:行号)」；不轻信子代理报告，关键链（用户报 bug 的、涉及权限/状态机的）自己验证
- **工具**：状态机链画转移图看 B4；素材走查完后开探索会话看 B5

### 步骤 4：输出走查报告

- **动作**：按模板输出报告（模板见 B8），让用户能直接判断风险
- **级别**：🔴 真缺陷 / 🟡 UX / 🟡 素材错误 / ⚪ 极低
- **工具**：问题排序看 B7 风险评分

### 步骤 5：修复闭环

- **动作**：修复+补测试 → 坑库编号 → CHANGELOG → AGENTS 基线 → 素材修正 → 记忆 → **回归重走**
- **回归重走**：按问题清单「受影响链路 S-ID」+ 冒烟集逐条重走，**全通过才关闭闭环**；未通过回到修复
- **工具**：功能变更后确定受影响链看 B6

### 步骤 6：迭代与停止

- **动作**：每轮输出「轮次小结」，四问判断——🔴 未清零？未收敛？回归有红？探索有新？→ 任一为是则继续下一轮
- **停止条件（全部满足才停）**：🔴 清零 + 本轮新发现 ≤ 上轮一半且连续 2 轮递减 + 回归全绿（受影响链+冒烟集）+ 连续 2 个探索会话零新问题
- **强制停止**：轮次上限 3 轮 / 预算耗尽 → 输出**残余风险报告**（剩余 P-xx + 风险分 + 跟踪建议）收尾，不假装全好

## B. 工具方法库（按需查，用到才读）

### B1 复杂度分级 L1-L9（写素材时用）

L1-L3 基础层覆盖主流程/往返/容错；L4-L9 进阶层逼出状态机矛盾、并发竞态、离线重放、权限漏洞、失败残留。**给"复杂案例"= L4+；"高复杂案例"= L7-L9。**

| 等级 | 名称 | 写法公式 | 示例（打卡清单） | 逼出的 bug |
|---|---|---|---|---|
| L1 | 单链直通 | 点哪→输什么→得什么，一条到底 | 开小程序→新建清单→输名称→保存→列表出现 | 主流程断裂 |
| L2 | 多步往返 | 多开关逐层开 / 三端往返 / 反复编辑 | 改周期为每周→切提醒开关→退出重进→再编辑 | 深链路状态残留 |
| L3 | 误操作恢复 | 手滑点错→程序行为→怎么恢复 | 误删清单→弹确认→取消→清单仍在 | 容错/边界 |
| L4 | 状态机长链 | 状态A→触发→B→触发→C…（含失败/超时分支） | 创建→完成→撤销→再完成→周期末自动推进→查提醒时间 | 状态机矛盾、循环死亡（P-1） |
| L5 | 并发竞态 | 甲做 X 的同时乙做 Y（同一资源） | 两台设备同时打开清单→同时点"完成"→两边结果一致 | 原子性、抢锁、双写（P-89） |
| L6 | 离线重放 | 断网→操作→恢复网络→重放顺序 | 断网→新建打卡+完成→恢复→重放→最终态与在线一致 | 队列顺序、最终态 |
| L7 | 权限矩阵 | 角色R × 操作集{a,b,c} 交叉执行 | 创建者/协作人/被移除者各自做：完成/撤销/改协作人 | 权限 UI 与云端不一致（P-6） |
| L8 | 边界极限 | 把正常链关键变量推到极限 | 额度=0 新建→被拒+提示；月末 31 号推进提醒 | 硬限制、空态、溢出 |
| L9 | 故障注入 | 在 X 步注入失败（推送失败/云函数超时/业务错误） | 完成时注入推送失败→操作仍落库→重试策略正确 | 失败分支、残留（P-B） |

### B2 覆盖矩阵对账（生成矩阵时用）

行 = 模块，列 = 场景类型，格内填 S-ID。**每列对应一个复杂度等级**：状态推进=L4、并发=L5、离线=L6、权限差异=L7、边界/空态=L8、故障注入=L9——某列整列空白 = 该复杂度案例缺失：

```
          | 正常 | 空态 | 边界 | 权限差异 | 并发 | 离线 | 状态推进 | 误操作 | 故障注入
创建模块  | S-01 | S-08 | S-08 |  S-07   |      | S-06 |          | S-03   | S-09
清单模块  | S-02 |      | S-08 |  S-07   | S-05 | S-06 | S-04     | S-03   | S-09
```

对账规则：
- **每行 ≥1 格、每列 ≥1 格**——整行空 = 模块没覆盖；整列空 = 场景类型缺失（如"状态推进"列空必漏 P-1 类循环 bug）
- **L4-L9 各至少 1 条**：项目具备对应能力（状态机/多端/离线/多角色/硬限制/外部依赖）时必须有素材
- 空出来的格补素材或写理由（如"单机应用无并发"）

### B3 规则真值表（遇到条件 ≥2 的规则时用）

覆盖矩阵覆盖不到**多条件组合规则**（如 按钮显示 = 创建者 ∨ 未完成 ∨ 未到期；推送 = 完成 ∧ 非静默 ∧ 未关闭）。判定表法列全组合：

```
条件: 创建者 | 未完成 | 未到期 → 动作: 显示完成按钮
  T  |  T  |  T  → 显示
  T  |  T  |  F  → 显示（未到期不影响）
  T  |  F  |  T  → 不显示（已完成）
  F  |  T  |  T  → 不显示（非创建者）
  ...（8 行全列）
```

- 组合 ≤20：全列，每行一次校验（可复用 S-ID 引用，不重复写链）
- 组合 >20：**pairwise 采样**（覆盖所有条件两两组合，依据 NIST SP 800-142：缺陷大多由少量参数交互引起）
- 矛盾组合（如前端显示按钮但云端拒绝，或静默丢数据）= 🔴 真缺陷

### B4 时序走查 5 问（状态机深度链时用）

对每个状态机（pending→sending→sent、done↔pending、循环推进）画转移图，逐转移过 5 问：

```
当前状态 →(条件/触发者/副作用/失败分支/超时)→ 下一状态
```

1. **触发者**：前端按钮 / 云端定时扫描 / 异步回调？——触发点必须真实存在
2. **校验方**：前端 UI 层 or 云端权威？——UI 显示条件与云端 requireCreator 不一致 = 权限漏洞（P-6）
3. **失败分支**：重试 / 回滚 / 静默？——网络错误保留队列、业务错误重试上限丢弃（离线重放）
4. **超时/重入**：抢锁超时回收（P-89）、幂等、防连点锁（operating/_completing/navLock）？
5. **副作用**：推送 / 推进 remindAt / 重算 memberIds / 清理 selectedIds？——遗漏 = 状态正确但数据残留（P-B）

### B5 探索会话 SBTM（素材走查完后开）

脚本化走查覆盖"已知的已知"，结构性漏掉"未知的未知"（竞态/文案/权限泄漏类，scripted+exploratory 结合缺陷发现率高 30-60%）。开 **1-2 个探索会话**：
- **charter**：`Explore [区域] with [资源] to discover [信息]`，如 `Explore 批量完成 with 多角色账号 to discover 权限泄漏与残留`
- **时间盒**：60-90 分钟硬停，防止漫游
- **debrief（PROOF）**：Past（做了什么）/ Results（发现）/ Obstacles（阻塞）/ Outlook（下一步 charter）/ Feelings（质量信心）
- **tours 定向**（可选）：Money tour（额度/支付路径）、Garbage-collector tour（清理/登出/残留，P-B 类）、Back-alley tour（无人用的隐藏入口）
- 发现进坑库编号（P-xx），标注来源「探索会话」，修复后同样回归

### B6 变更影响分析（功能变更回归时用）

3 步推导受影响链，不靠人肉猜：`git diff 变更文件 → grep 引用关系/调用图 → 匹配覆盖 C-ID → 筛出受影响 S-ID`。
**被改代码无任何链路触及 = 盲点**，补新素材后再走查。

### B7 风险评分 L×I（报告排序时用）

**风险分 = 发生概率 L(1-5) × 影响面 I(1-5)**
- L：代码新改/复杂/依赖多/历史出过错（新改+复杂 = 5）
- I：数据错误/功能失效 = 5，体验问题 = 2-3，仅文案 = 1
- **≥12 必修 / 8-11 建议修 / <8 可选**；高 L 的问题自动进深度走查验证

### B8 报告固定模板（步骤 4 用）

```
# N 条链路走查报告
## 总体结论：X 条通顺，Y 个问题（严重级别），Z 处素材与程序不符
## 问题清单（表格）
  编号 | 级别(🔴真缺陷/🟡UX/🟡素材错误/⚪极低) | 问题 | 位置 | 受影响链路(S-ID) | 风险分(L×I) | 影响
## 覆盖矩阵结论：盲区已补 / 仍空（如"状态推进列无场景，需补"）
## 走查验证的良好点（程序扎实的地方，证明不是空谈）
## 结论三问
  1. 链路逻辑通顺吗？
  2. 是补丁叠补丁吗？（权限/状态机/去重/离线是否有单点归属）
  3. 会无法操作/出 bug 吗？
## 建议处理（按风险分排序）
```

## C. 检查与沉淀（走查时对照）

### C1 关注点 Checklist

**代码审查点**（逐条过，对应历史坑 P 编号）：

- [ ] **权限 UI 一致性**：前端按钮显示条件 vs 云端 requireCreator（协作者点撤销被拒 = P-6）
- [ ] **事件绑定**：wxml 事件名必须静态字符串！`bind:tap="{{cond ? 'a' : 'b'}}"` 被当字面量方法名完全不触发（P-90）。模式切换在 JS 方法内 `if (cond) { ...; return; }` 分流
- [ ] **"更新数据 + 刷新渲染"同步**：markSelected 只更新统计不重写列表 → 勾选无视觉反馈（P-91）
- [ ] **状态机流转**：抢锁超时回收（P-89）；撤销后循环推进 remindAt（P-1）；完成态不推送
- [ ] **防连点/防重复**：operating 锁、_completing、导航锁 navLock、确认弹窗回调清空
- [ ] **离线重放顺序**：队列按序（create→remove 重放最终态正确）；网络错误保留队列、业务错误重试上限丢弃
- [ ] **并发安全**：complete 原子条件更新（where status pending）+ 竞态二次判断
- [ ] **边界**：24h 扫描窗口、月末/闰年推进、额度=0、空列表空态、时间已过顺延
- [ ] **协作人可见性**：memberIds 重算（移除后对方不可见）、改协作人触发 noticeAt 重排告知
- [ ] **素材与程序一致性**：素材每个操作都有对应真实入口（P-4）

**流程合规点**（方案自身执行到位）：

- [ ] 覆盖矩阵：无整行/整列空白；空格补素材或写理由
- [ ] 复杂度：有对应能力的项目含 L4-L9 链（不满足 = 矩阵对应列必空）
- [ ] 引用一致性：素材 S-ID ↔ 报告受影响链路 ↔ 坑库条目 ↔ 回归清单，四处一致
- [ ] 时序 5 问：状态机类素材全部过完 触发者/校验方/失败分支/超时重入/副作用
- [ ] 规则真值表：条件 ≥2 的规则列全组合或 pairwise，矛盾组合 = 🔴
- [ ] 探索会话：≥1 个 charter 会话，debrief 用 PROOF
- [ ] 变更影响：回归前先 diff→C-ID→S-ID；盲点补素材
- [ ] 风险评分：报告每个问题带 L×I，≥12 必修
- [ ] 停止准则：🔴 清零 + 收敛 2 轮 + 回归全绿（含冒烟集）+ 探索收敛，四项全满足才停
- [ ] 轮次上限：≤3 轮，超限输出残余风险报告收尾

### C2 产出落盘规范

1. **坑库**：问题记入 docs/09-pitfalls.md（P 编号递增，格式：现象/原因/解决/预防/相关），状态 `open → fixed → verified`
2. **CHANGELOG**：加版本条目（新增/变更/修复）
3. **AGENTS 基线**：关键坑同步到 AGENTS.md 顶部基线行
4. **素材修正**：素材层错误（写了不存在功能/漏前提）直接改描述，同步覆盖矩阵
5. **记忆**：走查结论（问题/良好点/能力边界）写入当日工作日志

## 附录：实战参考（三轮成果）

- 14 条操作链走查 → P-1 循环死亡（云端 uncomplete 推进）、P-2 编辑误授权（needNewPush 条件）、P-4 素材错误（计划置顶不存在）、P-5 告知需对方授权前提
- 7 误操作走查 → P-6 撤销按钮权限 UI 不一致（canUncomplete 改 creatorId 判断）
- 7 新功能走查 → P-B 批量模式下单条完成后残留 selectedIds 误删（onPlanComplete 成功剔除）
