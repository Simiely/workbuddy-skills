# illustrator-artboard-clip —— 画板建框收素材

职责单一：把**超出画板的素材**按画板边界收边（剪切蒙版），并保证画面内容一像素不变。不负责裁图数据、不负责排版、不负责导出。

> 一句话：**要"收边"就别动图，用画板矩形当剪切框** —— 素材的原始像素与摆放完全不动，剪切组随时可关可撤。

## 什么时候用

- 设计稿里有素材比画板大（背景大图按"出血"铺满，边缘溢出画板 2~5px 是常态）。
- 交付要求**严格不出血**：导出/印刷/切图时溢出部分会造成裁切错位、白边、拼接缝。
- 素材是**照片/位图**，重新裁图会损失像素或引入压缩噪点，不适合直接改图。
- 反过来：需要**真正裁掉像素**（缩小图片内容本身）时不要用本技能，那是另一回事。

## 反模式（务必避免）

1. **别直接裁图**（改像素数据 / 用 resize 缩框）—— 背景大图裁 2px 就得重编码位图，损失画质；而**画板框剪切**是零损失的，随时可逆。
2. **别用 `resize()` 改框来"裁"** —— 这会**缩放内容**（不是裁边），画面整体变小；而且 AI 2026 的 `TransformAbout` 枚举**不存在**，`resize()` 不能按常规写法调。
3. **别忘了剪切组要 ≥2 个对象** —— `group.clipped = true` 在组内只有 1 个对象时直接报 "There must be at least two page items in a group to create a mask"。
4. **别把对象用 `PLACEAFTER` 移进组** —— 那是"排在某对象之后"，会把对象移到组**外面**；移进组要用 `PLACEATEND`（组内最底层），裁切框用 `PLACEATBEGINNING`（组内最上层）。
5. **别忘了保持原叠放顺序** —— 剪切组要放回原对象所在的层序位置，否则遮挡关系变样（半透明遮罩、底图、叠图尤其敏感）。
6. **别用 `pageItems` 索引想当然** —— Illustrator 的 `pageItems` 集合**索引 0 是最前**（最上层），不是最后；据此判断"在谁前面"要先确认方向。
7. **别在脚本里写中文图层名做匹配** —— ExtendScript 按系统 ANSI 读无 BOM 的 UTF-8 脚本，中文字面量会被破坏，`getByName("图层名")` 直接返回 undefined。**名称只读取、不比较**；要定位就用结构特征。
8. **别在跨盘路径上启动 AI 脚本** —— 会弹**模态** "File not found"（路径还丢盘符）并**阻塞主线程**，不点掉弹窗脚本永不开始；必须把脚本复制到 Illustrator 所在盘再启动。

## A 主线（必做）

### 1. 只读侦察：定位溢出元素

先用 `scan_overflow.jsx` 扫出**所有超出画板且未在剪切组内**的元素（脚本会跳过已 clipped 的组）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_headless.ps1 `
    -Jsx scripts\scan_overflow.jsx -Log C:\ai\jobs\_overflow.txt -TimeoutSec 300
```

产出：每个溢出元素的图层、类型、边界、各边溢出量。
**铁律**：先看清单再动手——有些"溢出"是设计有意为之（出血铺满），别把该留的也剪了。

### 2. 备份原文件

改用户文件前必须留一份带时间戳的备份（同名 + `.bak-YYYYMMDD-HHMMSS.ai`）。
**铁律**：没有备份不开工。

### 3. 建画板框剪切组（核心动作）

`clip_to_artboard.jsx` 对每个溢出元素做四件事（脚本已封装）：

1. 以**画板矩形**建一个裁切框 PathItem；
2. 新建组 → 裁切框放**组内最上层**（`PLACEATBEGINNING`）、目标素材放**组内最底层**（`PLACEATEND`）；
3. `group.clipped = true`（开启剪切蒙版）；
4. 把组**放回原对象的层序位置**（前有邻居则 `PLACEAFTER`，否则 `PLACEATBEGINNING`）。

**铁律**：**不碰素材本身**——像素、位置、尺寸、图层归属全都不动，只加一层剪裁框。

### 4. 验收：画板内逐像素零差异

必须证明"收边后画面没变"。用 `imageCapture` 按**画板矩形精确取景**（不是作品外接矩形，否则取景会随收边而变导致比对错位）：

- 改前取景 PNG、改后取景 PNG → 逐像素 diff；
- 期望：**画板内 mean diff = 0，差异 bbox = None**；
- 若有差异，先查是不是取景矩形没对齐（`imageCapture` 只收两个参数，第三个 options 会报 "Illegal argument"）。

**铁律**：没有像素级证据，不算完成。

### 5. 复扫 + 写回

再跑一次第 1 步的扫描，确认「未加蒙版的溢出元素 = 0」，然后把结果文件写回原路径（保留备份）。

### 6. 沉淀

把新遇到的 API 坑补进 `references/api-pitfalls-ai2026.md`，并在 AGENTS/CHANGELOG 留痕。

## B 工具库

### B1 溢出扫描 `scripts/scan_overflow.jsx`
**触发条件**：动手前必跑；改完复扫。

- 输入：`-Jsx` 指向本文件、`-Log` 指向日志绝对路径；
- 行为：遍历所有图层，递归找 `visibleBounds` 超出画板且**不在 clipped 组内**的元素，逐条输出图层/类型/边界/溢出量；
- 输出：日志文件（UTF-8）；`unclipped overflow items: N` 即目标数；
- 注意：脚本**不含中文字面量**，图层名只读取；用 `Get-Content -Encoding UTF8` 读日志，否则 PS 5.1 按 ANSI 显示乱码。

### B2 画板收边 `scripts/clip_to_artboard.jsx`
**触发条件**：确认要剪哪些元素后。

- 行为：把每个溢出元素包进"画板矩形剪切组"，保持原层序；最后打印改后的层序快照；
- 输出：`C:\ai\jobs\_clip_out.ai`（路径在脚本顶部配置区）+ 完整日志；
- 注意：它会**同时处理所有未 clipped 的溢出元素**——若只想剪其中几个，先用 B1 的清单核对，或临时改脚本过滤条件。

### B3 零弹窗启动器 `scripts/run_headless.ps1`
**触发条件**：每次跑 B1/B2 都要用（否则会卡在模态弹窗上）。

- 行为：清旧实例 → 等进程真消失 → **把脚本复制到 `%SystemDrive%\ai\jobs\`（Illustrator 所在盘）** → 以该路径 `-r` 启动 → 轮询日志到 `done` → 返回语义化退出码；
- **为什么暂存到同盘**：实测跨盘路径（D: vs C:）会触发**模态** "File not found" 并阻塞 AI 主线程，不点掉弹窗脚本永不开始；同盘则直接跑通、零弹窗（实测 16s 跑完一次完整转换）；
- 退出码：`0` 成功 / `2` 参数或文件不存在 / `3` 旧实例杀不掉 / `4` 脚本内部 ERROR / `5` 超时（AI 未被杀，可能还在跑）/ `6` 超时且指定了 `-KillOnTimeout`；
- **铁律**：**超时不要杀 AI**（杀进程会腰斩脚本）；确认路径写法用反斜杠绝对路径；
- **启动器 `-Log` 必须与脚本内部的 `LOG` 完全一致** —— 不一致时表现为「超时且找不到日志」，
  极易误判成脚本没跑（本次实测就踩过一次：脚本写在 `_clip.txt`，启动器盯 `_clip_test.txt`）。

### B4 API 坑位速查 `references/api-pitfalls-ai2026.md`
**触发条件**：脚本报错时先查这里。

已实测记录（Illustrator 2026 / build 30 / Windows）：
`TransformAbout` 枚举不存在 → `resize()` 不可常规调用；
`imageCapture(file, rect)` 只收两参 → 传第三个 options 报 "Illegal argument"；
坐标 **y 向上** → 高度要按 `top − bottom` 算，写反得负数；
`pageItems` 索引 0 = 最前；
剪切组需 ≥2 对象、裁切框在最上层；
中文脚本字面量被 ANSI 破坏 → 名称只读不匹配；
`visibleBounds` 相对 `bounds` 更稳（部分对象 `bounds` 取不到）；
AI 坐标下渐变遮罩这类"故意出血"的元素也会被判为溢出，需人工判断。
